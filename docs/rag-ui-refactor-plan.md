## RAG 检查方法

- 核对已完成的四轮设置：重排 `minScore=-2.5`；向量与全文每路 `maxResults=10`；RRF 融合后 BGE Top-5；全部过滤时回退 RRF 前三条；提示词完整保留关键状态。
- 先运行当前代码的串行 100 题基线，降低并发资源压力；保留每一轮原始报告与失败信息。
- BadCase 沿“切片 → 改写 → 两路候选 → RRF → BGE → 生成”定位，先检查真实改写和候选，再决定修改。每轮只改变一个参数或逻辑。
- 检查量化 ONNX 分批的分数变化；已有内存保护必须保留，不能退回会挤爆本机内存的整批推理。
- 对关键状态和实体做重复检查；实际模型结果与本地确定性测试共同验证，不只依赖一次人工对话。
- 区分基础设施失败和检索未命中：外部连接失败单列，重试记录另存，100 题验收不能把失败排除后冒充全部通过。
- LLM Judge 关闭时生成/上下文指标记作未测量；检索达标后按需要验证 Judge 路径，任何质量结论说明测量范围。

## 设计方向与参考

采用适合知识库工作台的浅色界面：深蓝主色、清晰的页面标题和辅助说明、统一顶部四入口、分区卡片、紧凑可读的表格、明确的状态与错误提示。对话保留会话侧栏，评测保留四个业务标签。手机端保留所有入口和操作，长表格允许局部横向滚动。

参考 [shadcn/ui Dashboard](https://ui.shadcn.com/blocks?category=dashboard) 的公共布局、卡片和表格分区，以及 [Carbon Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) 的表格、工具栏、选择和批量操作规则。只借鉴界面组织与交互，不引入 React/构建系统来改写当前 Spring Boot 静态页面；优先抽离现有脚本和公共 CSS，保留业务实现。
